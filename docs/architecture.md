# prox V0.1 技术设计

## TD-001：Go Core + Bash Hook

状态：Accepted

日期：2026-09-05

### 决策

`prox` 使用 Go 实现核心 CLI，并通过 Bash Hook 完成当前 Shell 环境修改。

Shell 层只承担以下职责：

- 拦截 `prox on`、`prox off` 和 `prox status`；
- 保存当前 Shell 的环境快照；
- 执行核心程序生成的安全环境赋值；
- 检测环境漂移；
- 恢复原有环境。

Go 核心负责：

- 配置加载与校验；
- 代理 URL 解析；
- 地址脱敏；
- TCP 端点检查；
- HTTP/HTTPS 完整健康检查；
- 子进程环境计算；
- `prox run` 的进程替换；
- 命令输出和退出状态。

### 原因

纯 Shell 很容易实现最初的 `export` 和 `unset`，但 URL、IPv6、超时、TLS、错误分类和自动化测试会快速增加复杂度。Go 能够用标准库完成 V0.1 的全部核心能力，并产生无需运行时依赖的单文件程序。

普通子进程不能修改父 Shell，因此仍需要 Bash Hook。Hook 保持轻量，避免在 Shell 和 Go 中维护两份网络逻辑。

## Shell 集成协议

初始化：

```bash
eval "$(prox init bash)"
```

`prox init bash` 只输出静态 Bash 集成代码。错误写入标准错误，避免污染 `eval` 输入。

启用时，Hook 调用内部接口：

```bash
command prox __shell-env bash
```

该接口按顺序执行：

1. 加载并验证配置；
2. 检查代理端点；
3. 生成固定变量名、经过单引号转义的 Bash 赋值。

只有内部接口成功后，Hook 才保存旧环境并应用新环境。

`__shell-env` 是 Shell 集成协议，不属于普通用户日常命令。它在 V0.1 内部保持稳定，但不承诺跨主要版本兼容。

## 激活状态

Bash Hook 在当前 Shell 内保存：

- 是否由 `prox` 激活；
- 激活前每个变量是否存在；
- 激活前的变量值；
- 激活前变量是否导出；
- 激活后预期变量值；
- 当前代理的脱敏显示值。

这些状态不导出给普通子进程，也不写入磁盘。

## 健康检查

### 端点检查

使用带超时的 TCP 连接验证代理主机和端口。成功只说明端点可连接，不说明代理节点能够访问目标网络。

### 完整检查

完整检查构造一个显式绑定配置代理的 HTTP Client，不读取当前 Shell 的代理环境，因此：

- 当前是否执行过 `prox on` 不影响检查；
- `NO_PROXY=*` 不会绕过检查代理；
- 用户级 curl 配置不会改变结果。

默认使用 GET 请求访问：

```text
https://www.google.com/generate_204
```

并期望 HTTP 204。TLS 证书验证保持开启。

## `prox run`

Linux 实现使用 `execve` 语义，以目标命令替换当前 `prox` 进程：

```text
Shell
  └── prox run
        └── execve target
```

替换完成后：

- 不再存在额外的 prox 父进程；
- 标准输入、输出和错误保持不变；
- 信号直接到达目标进程；
- 目标命令退出状态自然返回给调用 Shell。

## 配置格式

V0.1 使用严格 JSON：

- 未知字段直接报错；
- 无配置文件时使用内置默认值；
- 超时使用 Go 风格的持续时间字符串，例如 `500ms`、`2s`；
- 只接受 `http://` Proxy URL；
- 不接受用户名和密码。

选择 JSON 是为了保持零第三方运行依赖。后续如果引入 TOML，应通过独立版本决策处理兼容和迁移。

## 依赖策略

V0.1 只使用 Go 标准库，不引入第三方 Go Module。

这不是永久限制。后续版本可以在明确收益大于供应链和维护成本时引入依赖。
